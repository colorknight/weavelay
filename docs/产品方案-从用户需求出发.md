# 织版：从用户需求出发的产品方案

桌面端 · 本地运行 · CPU 可跑 · 圈选识别区域 · 输出 JSON 定义 · 人工矫正兜底

织版把工艺 PDF 收成结构稳定、可核对、可归档的数据。识别留在本机 CPU 上；取值范围由人在图上圈定；一类文件长什么样，写在输出 JSON 定义里；对错在桌面上当场改完，确认后再进入实例。Excel 只是这份数据的投影。

采集有范围，数据有结构，写出有确认。产品对齐的是数据治理，而不是把字认全。

## 一、现场要收成的是数据，不是识字结果

工艺室每天处理的是扫描件和 PDF 规程。真正要交出去的，是结构稳定、可以改正、可以进入后续系统的一份数据。云端识别过不了保密；整本丢进批处理，错了才发现，返工比识别本身还贵；认完字再往 Excel 里贴，字段名和表结构每次都不一样，统计、归档、对接都跟不上。

这些约束决定了产品形态。图纸和工艺不出厂；工位电脑通常没有独立显卡；各厂版式不同，封面、工序目录、机加卡、检验卡不能共用一套写死的列头；识别会错，人必须对着原稿改即将入库的那一格；一类文件要有统一的数据形状，Excel 只是给工艺室看的视图。车间也装不了开发环境。

织版顺着这些约束做：Windows 桌面、本机运行、CPU 可跑，把范围、结构和核对做成主路径。

## 二、产品形态

打开 PDF，按页看原稿，在图上圈定取值范围，按该文件类型的 JSON 定义回填结构，人眼对照改正，确认后写出。识别是手段；范围、结构、核对才是产品。

主界面是交互式的。左侧 PDF 原稿，可缩放、翻页、圈选；右侧本页输出字段。图上哪一块、抽成哪一格、将进入 JSON 的哪个位置，始终同时可见，而不是「丢进文件夹等一份结果」。

工作分成两种模式。模板模式在样张上画圈、绑定字段、保存采集规则，一类文件做一次。应用模式按已保存区域取值，必要时临时重圈纠偏，对照改正后点确认，按输出定义写入实例 JSON。模板管「这一类页从哪采、采什么」；应用管「这一本怎么采、怎么改、写成哪份结构」。按钮按模式显隐，配规则和抽数不会互相踩。

## 三、本机桌面，CPU 可跑

文字、版式、公式都在工位上完成，不经过外网。推理走 CPU，不要求独立显卡，普通办公机即可。页型、圈选区域、输出 JSON 定义放在本机规则库里。便携包自带运行环境和识别能力，解压双击就能用，不必另装开发工具，识别本身也不必联网。

识别、规则、数据都在工位上闭环。

## 四、画圈选中识别区域

工艺卡一页字很密。整页通识时，表头会进数据，邻栏会串，空格会被邻行填上。业务人员其实知道「产品代号就在右上这块」——取值范围应由人圈定，而不是满页去猜标签旁边的字。

模板模式里，在 PDF 上画出矩形，点字段编号，把这块图绑到这个字段。字段名是要采的数据项，圈是采集范围，对应关系写入规则。应用时只在圈内取字或切表。普通字段圈值所在格；表格字段圈整张表，再按线切格填列。保存后，同类页沿用同一套圈。规则是配置。

某一页印刷偏移或装订裁切时，应用模式可以重新画圈再点字段重识。这次圈只留在本页会话，不写回模板，抽数不会把样张规则改坏。右键或 Esc 取消圈选。

圈选管的是采集边界：先声明采哪一块，再识别。输出 JSON 定义管的是写成什么样。两边合在一起，抽取才有治理。

## 五、按文件类型配置模板

工序目录、机加卡、检验卡的格子位置各厂不同，列头不能写死在程序里。织版以文件类型为边界：当前主场景是工艺规程，也可以扩展到检验报告、装配工艺。一类文件对应一套数据契约。

文件类型下再配页面类型——封面、工序目录、工艺附图、机加工序卡、检验卡、辅助工序卡等。字段由用户定义：圈选保存取值区域；表格用 `*表名:列1,列2` 声明列；含公式的字段或列在名称前加 `$`。一种文件类型还可以绑定一份 Excel 模板，作为给工艺室的落地视图。

整套规则打成模板包导出、导入，带着页型、圈选坐标、输出定义和 Excel 绑定。多工位共用同一份契约，结构不会在每台机器上各自漂移。

## 六、输出 JSON 定义：一类文件的数据契约

一页一堆键值无法治理。字段名今天叫零部件名称、明天叫零件名；工序有时是表、有时是散行；同一道工序跨封面、目录、工序卡，对不上号。没有结构就没有主数据，Excel 填得再整齐也只是一次性文件。

所以一类文件先约定契约，再往契约里填值。这份契约就是该文件类型的输出 JSON 定义，在设置里按类型编辑，失焦保存。占位符用业务字段名，打开定义就能看出这个位置将来填什么。

定义里先写根实体，例如零件；根上是产品代号、零部件名称、关重件标识这类标量属性；之下是工序、原料等集合，每条有列、有匹配键、有主键；集合条目下还可以挂从属卡片，例如某道工序下的机加卡字段。页面类型对应写入路径：封面写零件，目录写零件.工序，工序卡写零件.工序.机加工序。`{{字段名}}` 把页面上采到的项对齐到模型里的名，不必识别完再手工拼结构。

确认之后得到的是这一本的实例 JSON。定义稳定，实例按本积累。产品代号属于零件，工序号属于工序集合，不会整页平铺后再靠人脑归类。目录页建出工序条目，后面的机加卡、检验卡按匹配键补到同一条上，只补字段，不整段重写，也不重复建条。未确认的页不进入实例，半成品进不了主数据。

下游——Excel、归档、对接、对账——都消费同一份结构。Excel 模板可以换，JSON 定义保持稳定。

## 七、对着原稿改，确认才入库

批处理跑完才发现整本错了，成本最高。织版让人边看图边改即将进入结构的那一格。左右对照，圈画在原稿上，文字行和表格格可点，点格出旁白。第一页出结果即可看，不必等全书结束；上次打开的 PDF 会记住，中断后续得上。设置窗口可以拖到一侧，对照 PDF 配圈选和输出定义。翻页、选页型、应用、圈选后重识、特殊符号，都有快捷键。

识别仍会把直径符认错、把空格吞掉、把同一格两行字拆成两条。字段值可以直接改；也可以重圈后点字段再识一遍，只改本页。表格弹窗上下对照，上面是 PDF 裁图，下面是识别表，双击编辑，确定写回。页型选错就手选，字段骨架按新页型重建，避免写进错误路径。F4 弹出工业符号键盘，⌀ ± ° ℃ μ Ω 和常用上下标不必手敲。必须点确认，才按输出定义写入累计 JSON。机器填，人签字。

空格保留，不从邻行补字。表格按印刷线切行，同一格里的多行字留在同一条记录里。看起来完整、实际串行的脏数据，尽量在确认前拦住。

工艺卡里大量是表、公差、直径符和嵌入公式。表格在圈定范围内按横竖线切物理格再填字，线不够则按文字位置推断。标记含公式的字段或列，会先取出公式小块写成 LaTeX，文字仍按区域识别，再按阅读顺序拼回该字段。弹窗里公式是渲染后的样子，改的时候看得见。

## 八、Excel 是投影，现场可以原样装走

工艺室已有标准工艺卡，必须能填进去；但主数据不能绑死在某张 xlsx 上。确认后先写入实例 JSON，再按绑定的 Excel 模板，把 `{{产品代号}}`、`{{材料表,2,零件重量kg}}` 等占位符从 JSON 投影出去。整表可以展开数据行，带路由时可以跳到对应工序类型的工作表。导出目录可预置，文件名跟 PDF。同类工序合并写入同一张表。

便携包解压双击即可，授权用机器指纹导入。模板包把页型、圈选坐标、输出 JSON 定义和 Excel 绑定一起带走，多工位共用同一份数据契约。

## 九、一类文件配一次，每一本照此收

配契约时，先选定文件类型，作为数据边界；再配页面类型和字段；写出根实体、属性、集合、匹配键和各页写入路径；打开样张，切到模板模式，按页画圈绑定字段并保存；最后绑定 Excel 视图。复制到其他工位时导出模板包。

日常抽数时，打开 PDF，切到应用模式，逐页确认页型，按已保存的圈取值。印刷偏移就重圈重识，只改本页。对着原稿改完，点确认写入实例 JSON。全书完成后，由这份 JSON 投影出 Excel。

产品有意把边界划清：识别不送出工位；进正式数据必须有人确认；不用整页通识代替圈选；不以 Excel 为唯一数据源；不把某一家厂的列头写进程序；不要求独立显卡；应用模式的重圈不覆盖样张规则。

## 十、收束

现场要的是：在工位上对着原稿，把这一类工艺文件收成结构稳定、可核对、可归档的一份数据。织版把力气花在本地与 CPU 上的桌面闭环、圈选出来的采集范围、作为数据契约的输出 JSON 定义、对着原稿的人工矫正，以及作为投影的 Excel。

演示时走通一条即可：打开真实工艺 PDF，打开该类型的输出 JSON 定义，在模板模式圈两个字段，在应用模式抽出值，改错一格后确认入库，再打开由 JSON 填好的 Excel。走通的是治理闭环，而不是识字率。
